# Second Ball IQ

Explainable live football intelligence, built for the Microsoft x Premier League "Inside the Game" hackathon.
Second Ball IQ detects meaningful changes in a live synthetic match, explains them with evidence, adapts them to each
viewer, and proves its own accuracy against known ground truth. Every pressing, possession or tactical read that goes to air is put to a tactical test: a measurable criterion and a deadline are locked with Decision-1's estimate, the Watch Party votes on whether it will hold, and the match events settle it (met, not met or inconclusive) into a public record. Fans can ask it anything about the match and get checked, evidence-backed answers, watch together in a Watch Party with polls and crowd predictions against Second Ball IQ, and pick how deep the explanations go, from Learn the Game for beginners to full tactical detail. It reads each team's shape and each player's role (false nine, shadow striker, wing-back) and spots when a coach changes the plan. Before every set piece it predicts where the ball goes from the taker's history, a live commentator calls the big moments in an excited voice, and any moment can be rewound on the tactics board. In the coach's corner, two coach agents propose rival plans for a team, Decision-1 picks between them with a probability for each, both plans are tested by the match, and a public record counts how often the pick was the plan that held; a what-if sandbox moves a team on the live tracking frame and asks the same arbiter whether the change would help. All data is synthetic: fictional clubs, players, matches and seasons generated by Match Forge.

## Layout

| Path | What it is |
| --- | --- |
| `src/MatchLens.Contracts` | Versioned schemas shared by every component: `MatchEvent`, `MatchInfo`, `Insight` v1, `GroundTruth`, and the JSON settings. |
| `src/MatchLens.Forge` | Match Forge: deterministic synthetic match generator with scripted scenarios and measured ground truth. |
| `src/MatchLens.Analytics` | The analytics engine: live match state, rolling windows, seven detectors (including shape, roles and tactical shifts), the texts the gates read, and MCP-shaped queries. |
| `src/MatchLens.Agents` | The multi-agent workflow on Microsoft Agent Framework: Tactical Analyst and Narrator agents, the Validator, the Decision-1 gates and template fallbacks, tactical tests, and the coach's corner (two coach agents, Decision-1 as the arbiter). |
| `src/MatchLens.Decisions` | Microsoft-Decision-1 client and the triage and grounding gates. |
| `src/MatchLens.Server` | The live server: plays a match on a clock, runs every candidate through the agents, streams events, agent steps and insights over SignalR, hosts the editor queue, and exposes the engine as an MCP server at `/mcp`. Serves the web front end from `wwwroot`. |
| `web` | The web front end (React + Vite + Fluent UI): the desktop studio (live board, on-air preview, review, agent trace, evaluation) and the fan companion for phone and desktop. Builds into the server's `wwwroot`. |
| `tools/MatchLens.Forge.Cli` | `forge` command line: list, generate, check and inspect matches; replay them through the engine and evaluate the detectors. |
| `tools/MatchLens.Pipeline.Cli` | `pipeline` command line: run a match through the whole pipeline, offline or live, and write the insights. |
| `spikes/DecisionSpike` | The Decision-1 spike and its test cases (see `docs/decision-1-spike.md`). |
| `scripts/mock_systemone.py` | Offline stand-in for the Decision-1 endpoint. |

Requires the .NET 8 SDK or newer. `MatchLens.Agents`, the server, the pipeline CLI and the tests need NuGet packages; the generator and the engine build offline.

```bash
dotnet build MatchLens.sln
dotnet run --project tools/MatchLens.Forge.Cli -- list
dotnet run --project tools/MatchLens.Forge.Cli -- check --seeds 30
dotnet run --project tools/MatchLens.Forge.Cli -- generate demo-match
dotnet run --project tools/MatchLens.Forge.Cli -- evaluate --seeds 30
dotnet run --project tools/MatchLens.Forge.Cli -- replay demo-match
dotnet run --project tools/MatchLens.Forge.Cli -- autoevent --seeds 4                   # auto-eventing from tracking, scored
dotnet run --project tools/MatchLens.Forge.Cli -- xt                                     # fit the xT grid and the completion curve
dotnet run --project tools/MatchLens.Forge.Cli -- spatial --seeds 4                     # pitch control, lanes, better passes, checked
dotnet run --project tools/MatchLens.Pipeline.Cli -- demo-match --offline
dotnet run --project tools/MatchLens.Pipeline.Cli -- demo-match --offline --plant number   # fault drill
dotnet test tests/MatchLens.Tests                                                          # unit tests, no models

# The live app: open http://localhost:5080 (studio), /fan (fan view), /judge (the demo match from 38') or /overlay (broadcast graphics)
dotnet run --project src/MatchLens.Server
```

While a match plays, the coach's corner runs on its own every fifteen minutes for each team; to try it at once, open
Coach's corner in the studio (or Analysis › Coach's corner in the fan view) and press "Ask the coaches now", or call
`POST /api/coach/{teamId}`. The what-if sandbox is below it (`POST /api/whatif`). Both need the live models for the
coach agents and Decision-1; without them the coaches fall back to plain rules and there is no pick.

### Recording a test run

The server writes its log to `logs/server-<date-time>.log` as well as the console: every model call with its time and
tokens, every Decision-1 answer with its probabilities, the coaches' proposals, tests as they lock and settle, and
what-if runs. To record what the screens showed, run the capture script next to the server:

```bash
cd scripts/capture
npm install
npx playwright install chromium        # once
node capture.mjs --judge --exercise    # starts the demo match at 38', asks the coaches, tries a what-if
```

It saves screenshots of the studio, the fan view (phone and desktop) and the overlay (each time its graphics change), the
match state every round, and any browser errors, into `captures/<date-time>/`, and stops a minute after full time.

The built front end is checked in under `src/MatchLens.Server/wwwroot`, so the server runs without Node. To change
the UI, see `docs/server.md`. `Dockerfile` builds both into one container.

See `docs/match-forge.md` for the generator, `docs/analytics.md` for the engine and detectors, `docs/agents.md` for the agents and the workflow, and `docs/server.md` for the live server and the UI.
